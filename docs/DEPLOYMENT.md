## 腾讯云独立版

`npm run build:selfhost`产生`selfhost-dist/server.mjs`、`client/`和`migrations/`。Node运行需要`BMTI_ADMIN_HASH`、`BMTI_PUBLIC_ORIGIN`、`BMTI_DATABASE_PATH`与可选`PORT`，秘密只在运行时注入。SQLite必须放在稳定的数据目录，不随发布替换；连同WAL应使用SQLite在线备份或停服一致备份。

Nginx负责HTTPS、HTTP跳转和代理，Node仅监听回环。systemd模板限制写入目录、使用独立私有环境与开机自启。证书续期由服务器任务配置，实际续期和重启恢复需单独验收。

`selfhost/deploy/`是现有服务器专用部署材料，含固定域名、用户、IP和已知基线：

- `activate.sh`验证校验清单、环境、Nginx、证书与健康接口，备份并生成回滚脚本。
- `finish.sh`先核对包，再执行历史基线修复与激活。
- `repair-nginx-baseline.sh`只处理当时已确认的悬空include，**不是通用Nginx修复器**，不能当作新服务器安装步骤。

不要在未知服务器直接执行这些脚本。维护现有部署时由负责人核对当前基线；新服务器先调整用户、路径、域名、DNS、代理与证书配置，编写自己的可回滚部署计划。

重新构建会清空输出目录。完整发布包需另外复制`selfhost/deploy/`、记录`release.json`、生成全文件`SHA256SUMS`；不包含数据库、私有环境或口令。2026-10-29最后一次修订仅替换静态资源，后端保持原发布版本。

## 发布检查与回滚

1. PR写明题库、计分和呈现各版本以及旧记录兼容方式；新题本先解决[多版本限制](SCORING.md#版本与兼容限制)。
2. 单元、类型、构建及适用的隔离HTTP、浏览器测试通过。
3. 记录源码提交与产物哈希，备份数据、配置和旧产物，准备具体回滚命令。
4. 在隔离环境验证后，由维护者执行已授权的生产更新；生产口令不交给普通研究贡献者。
5. 外网核验HTTPS、健康、页面资源、合成答题／报告、记录隔离及原有服务健康；不读取真实答卷，清理本轮合成记录。
6. 记录真实服务、浏览器与手机各自结果；配置成功不能当作实际重启、续期或效果验证。

回滚恢复上个应用和配置，不自动用旧数据库覆盖上线后的新记录；数据库变更另设兼容与恢复方案。静态修订应保留旧哈希资源，避免已打开页面失效。

## Sites旧站

保留`.openai/hosting.json`的project_id与D1绑定，通过Sites原生源码同步、构建、保存和部署流程更新。运行时秘密单独配置，不随GitHub上传。若通过Codex Sites插件发布，遵循该插件技能的当前工作流；普通GitHub推送不等于Sites发布成功。
