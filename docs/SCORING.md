# 计分、呈现与版本

权威实现：`lib/hgp.ts`；独立呈现：`lib/portrait.ts`；题库：`lib/questions.json`。规则与示例详见[完整题本](research/HGP_V02_QUESTIONNAIRE_2026-10-28.md)。模型与阈值均待验证，不展示准确率或人格百分比。

## 当前 HGP-0.2

32题，V/R/T/A/S/F/I/C各4题。每题只给所属端点评分，0—4正向计分，端点之间不互相扣分。`unable`、`skipped`不计0；每端至少3个有效数值答案才计算均值。

抽样8—32题，每端数量为总题数除8的下取整或上取整，题号不重复，顺序随机。低于24题至少有端点不足3题，不能形成完整角色；24题以上也不保证有角色。

## 单维判断顺序

| 优先级 | 条件 | 原分类结果 |
| --- | --- | --- |
| 1 | 任一端均值为null | 信息不足，不定字母 |
| 2 | 两端均值都≥3 | 并重，不定字母 |
| 3 | 两端均值都≤1 | 较少符合，不定字母 |
| 4 | 其余情况，均值差≥1 | 选较高端字母 |
| 5 | 其余情况，差值<1 | 暂无明显侧重，不定字母 |

双高／双低优先于差值，例如3与4仍是并重，0与1仍是较少符合。只有四组全有字母，才查16角色表。内部未定代码允许包含`?`，界面不把它当作用户画像标题。

## 呈现修订 portrait-20261029

`presentPortrait(report)`读取已保存的八端均分，生成具体摘要、状态与差值解释；不修改报告原值。差值大于0但小于1显示“分数略高”，同分显示“得分相同”，双高／双低和缺失分别解释。略高不是统计显著或经过验证的新分类门槛。

例如V/R=2.75/2.25、T/A=2.75/3.25、S/F=3/2.75、I/C=3/2.25，仍不形成角色，但报告写明愿景、试做、有序、自主略高。测试用合成逐题答案复现这些均分，没有保存真实逐题答案。

## 版本与兼容限制

当前`attempts`只保存`question_ids`（题号列表）、答案与完成时的报告，没有独立题库版本字段或不可变题文快照。GET与未完成记录提交时都通过当前`questions.json`解析题号。已完成报告直接读已保存JSON，展示层会用当前`portrait.ts`重新解释其均分。

因此，**目前不能声称已支持安全的多版本题库发布**：直接改旧题号的文案、端点或删除题号，会影响旧记录读取和进行中的答题；仅修改`VERSION`常量不能解决这个问题。

后续发布新的题目、端点、分类阈值前，先实现并验证：

1. 不可变题库版本或完整题文／端点快照；每次开测固定版本。
2. 按记录版本解析题目与计分；进行中测试沿用原规则。
3. 报告标记题库、计分与呈现版本；旧报告不被静默重算。
4. 旧记录缺少版本时的明确迁移、回退与测试方案。

文案与样式调整可单独记录呈现修订，但仍要检查旧报告及缺失情况。新题本先在独立分支、合成数据和隔离库验证，不直接在生产覆盖旧题。

## 修改核对

题文变更需同时更新研究题本、JSON和经审阅的冻结参考；不要只改测试参考使测试变绿。计分变更需提供前后案例、测量理由、分类影响及兼容方案。每项描述应能追溯到实际测量内容，不从角色推断能力、病症或困难。
