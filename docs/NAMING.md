# BMTI 命名与兼容

正式简称：**BMTI**。英文全称：**Better Me Type Indicator**。

理念：**了解自己，探索边界，成为更好的自己。**

名称表达自我探索和成长方向，不代表已经验证人格、能力或陪伴效果。本次只改名称与兼容读取，32道题、八端均分、分类阈值和16角色映射不变。

## 项目约定

- 包名与GitHub仓库：`bmti`；本地独立项目目录：`sites/bmti/`。
- 领域模块：`lib/bmti.ts`；当前计分版本：`BMTI-0.2`。
- 配置：`BMTI_ADMIN_HASH`、`BMTI_PUBLIC_ORIGIN`、`BMTI_DATABASE_PATH`；HTTP检查：`BMTI_TEST_URL`、`BMTI_ADMIN_PASSWORD_FILE`。
- 新Cookie与草稿：`bmti_admin`、`bmti_visitor`、`bmti-draft-…`；新SQLite迁移元数据表：`_bmti_migrations`。
- 研究文档、测试文件、部署模板统一BMTI命名；部署模板使用`heretoo-bmti`服务与目录。

## 历史记录兼容

`lib/legacy.ts`集中保留旧标识：`HGP_…`环境、`hgp_admin`／`hgp_visitor` Cookie、`hgp-draft-…`和`_hgp_migrations`。这些是读取旧数据所必需的兼容键，不再作为产品名称。相应旧字符串也会出现在兼容测试中。

- 新环境变量优先；已有私有环境暂时未迁移时读取旧变量，不要求重新生成管理口令。
- 旧访客token沿用原owner摘要，开新测试时写新Cookie，已有报告仍可访问。
- 管理登录写新Cookie；旧会话仍可读取；登出撤销本轮携带的新旧会话并分别过期Cookie，避免旧会话残留。
- 草稿优先新键，缺少新键时读取旧键；提交和删除时清除两种键。
- 已有SQLite沿用旧迁移表与校验和，防止改名后重复执行迁移；全新数据库创建新表。业务表、答案和原报告不因名称变化改写。
- 已保存的旧版本前缀只在页面等价显示为`BMTI-0.2`；历史报告JSON保留原值，不伪装成一次新测评。

旧Sites域名保留，因为浏览器Cookie按来源隔离；更换旧域名会影响原报告访问。项目title和页面品牌改为BMTI，托管project_id及数据绑定保持不变。Git历史与第三方依赖的完整性哈希保留原样，不为消除字符串而改写历史或哈希。

## 发布边界

本轮将名称修订同步GitHub、腾讯云静态页面与Sites。腾讯云后台的已运行服务名、私有环境、数据路径和现有二进制不会仅因改名被强制迁移；当前静态更新不重启后台。新BMTI部署模板尚需负责人根据真实路径执行迁移后激活，不能把模板的新路径当作服务器已经存在的路径。

## 验证

- 12项领域／呈现／名称兼容测试，5项SQLite测试；10项隔离HTTP测试，包含旧访客与新旧管理员会话登出。
- 类型检查、独立构建；浏览器首页理念、标题、390px布局与管理页。
- 原题文冻结参考保持32题不变。测试与命名统一不证明量表有效性；真实研究和手机验收另行开展。
